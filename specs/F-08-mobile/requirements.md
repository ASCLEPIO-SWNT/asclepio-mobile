# F-08-mobile — Dictado español en el dispositivo

Brief global: `../asclepio-api/docs/product/features/F-08.md` (F-08.AC1–AC5); ADR0006 de API y ADR0001 móvil (minSdk31). Autorización: plan completo del usuario **«PLEASE IMPLEMENT THIS PLAN»**, 2026-10-29, `docs/mobile-migration.md` bloque F-08-mobile. PA-F08-1 queda resuelta para esta implementación por el plan: dictado conserva provenance aunque se edite. PA-F08-2 se ejecuta con soporte/fallback comprobados en el parque minSdk31+, sin prometer voz local instalada en todo teléfono.
Contrato: consume **0.4.0**, sin cambios. Dependencias: F-02-mobile y UI-01-mobile, y bloques anteriores cerrados según orden del programa. **Spec futura**, sin activar ni código.
RNF: RNF-05, RNF-06, RNF-10, RNF-12, RNF-13, RNF-14, RNF-18.

Glosario: **dictado** = recognizer on-device español es-CO/es para el motivo del preregistro PATIENT; **sesión de escucha** = generación local ligada a pantalla, formulario y sesión autenticada; **texto aceptado** = resultado final no vacío insertado en el borrador, nunca un parcial; **guía** = TTS estático de UI-01, independiente del reconocimiento. La interfaz mantiene cinco idiomas, pero el idioma de reconocimiento de este slice es exclusivamente español.

## Requisitos

- **R1** (Por evento) Cuando se abra el motivo de preregistro de un paciente autenticado, el sistema deberá comprobar en tiempo de ejecución la disponibilidad de reconocimiento on-device y español con las capacidades de la API instalada, dejando texto disponible si no hay servicio, idioma/modelo local o soporte del fabricante. (→ F-08.AC1)
- **R2** (Ubicuo) El sistema deberá crear reconocimiento exclusivamente con `SpeechRecognizer.createOnDeviceSpeechRecognizer` en API31+, limitado a es-CO/es, sin recognizer genérico, ASR remoto ni fallback basado solo en EXTRA_PREFER_OFFLINE. (→ F-08.AC1, F-08.AC2; RNF-06)
- **R3** (Por evento) Cuando el usuario pulse Dictar, el sistema deberá solicitar RECORD_AUDIO si falta y comenzar escucha únicamente si se concede, sigue vigente el contexto y hay soporte local, sin pedir permiso al arrancar la app ni grabar automáticamente al entrar. (→ F-08.AC5)
- **R4** (No deseado) Si el permiso se deniega/revoca o no puede abrirse el micrófono/reconocedor, entonces el sistema deberá mostrar un mensaje local y conservar el motivo escrito y la edición/envío por texto, sin recurrir a reconocimiento de red ni repetir permisos en bucle. (→ F-08.AC1, F-08.AC2, F-08.AC5)
- **R5** (Por estado) Mientras haya una escucha o procesamiento de resultado, el sistema deberá mostrar su estado y controles Detener/Cancelar, impedir otra escucha simultánea y no enviar el preregistro hasta resolver o cancelar explícitamente la escucha. (→ F-08.AC2, F-08.AC3)
- **R6** (Por evento) Cuando llegue un resultado final no vacío de la escucha vigente, el sistema deberá incorporarlo una sola vez al motivo conservando el texto previo, permitir revisarlo/editarlo y mantener la validación/contador de 2000 sin truncar ni enviar automáticamente. (→ F-08.AC3, F-08.AC4)
- **R7** (No deseado) Si la escucha termina sin texto final, con error o cancelada, entonces el sistema deberá conservar el borrador y su provenance previos, mostrar el estado local aplicable y mantener la alternativa escrita. (→ F-08.AC1, F-08.AC3, F-08.AC4)
- **R8** (Por evento) Cuando un borrador haya incorporado texto de dictado, el sistema deberá enviar `complaintSource=VOICE_ON_DEVICE` aunque luego se edite o reescriba manualmente; sin ningún resultado de dictado aceptado en ese borrador deberá conservar `TYPED`. (→ F-08.AC4; plan móvil, provenance)
- **R9** (Por evento) Cuando se envíe el preregistro revisado, el sistema deberá conservar el POST existente con únicamente siteId, chiefComplaintText trim y complaintSource, sus validaciones/errores/guardas y ninguna hora, actor, tenant o audio adicional. (→ F-08.AC3, F-08.AC4; F-02.AC8; RNF-10, RNF-14)
- **R10** (Por evento) Cuando se abandone la pantalla, cambie sesión/formulario, se cancele la escucha o la app pase a segundo plano, el sistema deberá cancelar/liberar el recognizer y descartar callbacks/permisos pendientes de esa generación sin modificar otro borrador o reiniciar micrófono automáticamente. (→ F-08.AC2, F-08.AC3, F-08.AC5)
- **R11** (Por evento) Cuando se rote o cambie idioma/tema durante el flujo, el sistema deberá detener la escucha anterior, conservar solo el borrador y provenance ya aceptados en ViewModel y requerir una nueva acción de Dictar para escuchar, sin restaurar audio ni resultados parciales desde estado guardado. (→ F-08.AC2, F-08.AC3, F-08.AC4)
- **R12** (Ubicuo) El sistema deberá mantener audio, transcripción y provenance de borrador únicamente en las ubicaciones RAM autorizadas, sin archivos de audio, logs, uploads, SavedStateHandle, DataStore o contenido clínico para la guía, descartando el borrador al cambiar sesión/formulario o morir el proceso. (→ F-08.AC2, F-08.AC3; RNF-05, RNF-06)
- **R13** (Por evento) Cuando se active dictado o guía estática, el sistema deberá detener la otra modalidad para no reconocer su narración, manteniendo controles y estado independientes y sin que TTS lea el motivo/transcripción. (→ F-08.AC2, F-08.AC3; plan móvil, guía separada)
- **R14** (Ubicuo) El sistema deberá ofrecer dictado solo en el preregistro PATIENT y textos/estados/errores accesibles en los cinco idiomas de UI-01, indicando que reconoce español, con alternativa escrita operable a 320 dp/tablet/texto al 200 %/TalkBack/teclado y sin añadir dictado STAFF u otros idiomas de reconocimiento. (→ F-08.AC1, F-08.AC3, F-08.AC5; RNF-12, RNF-13)
- **R15** (Ubicuo) El sistema deberá distinguir en la evidencia las pruebas de lógica/fallback y POST contractual de la escucha/transcripción real en dispositivo con modelo local, sin declarar reconocimiento audible o integración API/DB real por haber usado motores o servidores simulados. (→ F-08.AC1, F-08.AC2, F-08.AC4; plan móvil, verificación)

## Preguntas abiertas

Ninguna decisión de producto pendiente para el slice. Español es-CO/es, provenance tras edición, minSdk31 y fallback escrito están resueltos por el plan/ADR. La disponibilidad de motor/modelo físico se detecta y documenta, no se presupone. No se añaden descarga automática de modelos, grabación, ASR de red ni otras lenguas.
